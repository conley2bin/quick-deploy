# 长期个人代理：可替换节点与独立订阅

> **状态：设计提案，未实现、未部署。** 决策日期：2026-10-17。
> 现有 `setup.sh` / `lib/` 仍是旧的代理＋Tailscale＋公司8743混合实现；不能按本文当作已经可用。
> 本文的命令、新 flags、目录与工作流都是未来接口；[README](README.md) 下方仅保留历史实现说明。

## 1. 推荐与边界

**默认恰好一台数据 VPS，不假定备用，也不要求购买第二台。** 初始协议为 **VLESS＋REALITY＋Vision / TCP443**，复用现有 sing-box 编排与回退机制。
接受冷替换停机：旧机故障到新机租用、部署验收、发布并刷新完成之间，代理可能不可用。
订阅仍放在运营者控制、与数据节点不同故障域的 **HTTPS443 静态托管**；它不是第二台租用 VPS。
托管商可提供已有可信TLS域名，不要求另外购买域名；具体服务待预算、权限与信任确认。
本设计不授权购买、部署或上传凭据；Xray仅为待评估替代，不默认维护第二套后端。

| 组成/模式 | 成本与边界 |
|---|---|
| 默认方案 | 一台数据VPS＋独立静态托管；域名可由托管商提供，接受冷替换停机 |
| 降级同机源 | 数据机8443可额外提供订阅，但整机/IP失效时一起消失，不能是唯一恢复路径 |
| 人工恢复 | 离线文件/二维码；若用户已有且愿意使用机场，可保留独立订阅手动切换，但不是必需条件 |

可选预登记订阅镜像；客户端自动切换URL不作保证。机场同样不被假定为专线、永不被封或自动接管。
将来只有用户主动改变单VPS预算时，才另评估不同供应商/ASN的第二节点（如经验证的Trojan/TLS）；那是额外扩展，不是当前采购、运行或验收前提，也不消除共同故障。

### 协议如何帮助，以及不能解决什么

REALITY 的认证与目标站转接降低部分主动探测区分度，TLS 模拟针对握手分类；仍有时序/长度、IP/ASN和域名关联风险。[1][4]
Vision 不代表统计不可识别；TLS-in-TLS 研究能提示区分面，但其美国 ISP 数据不是 GFW 部署或精确 REALITY 胜率。[2]
Trojan 的真实 TLS/证书与正常 fallback 提供另一认证/握手路径，不保证比主协议更难封。[9]
Hy2/TUIC 的 QUIC 拥塞表现不等于抗封；UDP限制与 QUIC-SNI 过滤要独立看待。[3][10]
Hy2 仅在固定/移动网络实测有收益后另行评估，不自动加到当前节点；端口跳跃、obfs 不是免封机制。
Naive 的客户端实现约束、SS2022 的高熵外观均不足以取代本轮初始协议，不增加默认维护项。
默认只开需要的协议，避免六协议叠加；“一个 IP 只能一种协议”不是普遍定律。

### REALITY 目标与版本政策

- 现有 **sing-box 1.14.3 仅是候选 pin**，不是已获准发布的版本或本设计的兼容保证。[5]
- 上线前锁定并验收：签名软件包、服务端核心、Mihomo、Shadowrocket、目标站/SNI这一完整组合。
- 最近 keyshare/MLKEM 漂移要求成对测试；不向所有版本硬塞同一开关，不放宽认证/证书检查来掩盖失败。[4][5]
- 目标由声明配置选择，不照搬博客中的 Microsoft/Apple 站点；按支持版本验证 TLS、ALPN、可达性和实际握手。
- self-steal（本机 HTTPS 作目标）是可测试选项，不是默认域名/证书要求；社区经历不能证明它更不易封。
- 若真实客户端组合失败，停止发布并排查；必要时另行评估Trojan，不假定有现成备用，不自动升级latest或换引擎。

REALITY不盗取、下载第三方私钥，也不取得第三方证书所有权。目标站的公开TLS响应/证书用于外观与未认证连接转发。[4]
我们的服务器持有自己生成的REALITY私钥；客户端配置我们的公钥、short-id及VLESS用户认证材料，而不是第三方私钥。
因此代理可用**IP＋经过验证的第三方目标站**，不必拥有域名或申请自己的证书；这不等于完美模拟或不会封。
订阅HTTPS是另一件事：它仍须可信TLS名称和有效证书，可以由静态托管商提供。

## 2. 组件、身份与秘密的归属

```text
管理笔记本：仓库 + 非秘密策略 + 私有库存/密钥/恢复集
  ├─已核验 SSH → 唯一数据节点（只持有自身配置和认证材料）
  └─独立发布通道 → 静态订阅源 HTTPS443 → 桌面/手机
                                           ↘ 预登记镜像或离线导入（人工）
```

| 对象 | 生命周期与来源 |
|---|---|
| 设备/账户、订阅 token | 长期稳定；每设备独立，token泄露时可单独撤销/换发 |
| 逻辑槽 `SELF-main` | 唯一在用节点的稳定显示名称；映射到已发布实例 |
| `node-id` | 自动生成的一次租用/实例ID；记录供应商、IP、到期日和状态 |
| 节点密钥、设备×节点认证 | 新租节点默认新建；与过期/失控旧机不共享私钥或UUID/密码 |
| 发布代次 generation | 某次完整发布；记录节点映射、摘要和撤销版本，不以DNS当作身份库 |

凭据保留只允许显式选择的、仍可信且受控的原机重建；不能作为到期换供应商的默认行为。
新节点靠**不变订阅 URL＋REFRESH**下发新公钥/认证；仅改 DNS 不能更新缓存认证或撤销旧服务器。
公开仓库只保存 schema、平台/版本政策、模板和非秘密默认值；实际 IP/租期等库存也默认留本地。
私有区为仓库外0700目录/0600文件；保存 token、节点密钥、设备认证、发布写凭据和恢复集。
恢复集离机加密保存，包含可信部署包/校验依据、库存、身份映射和发布代次；定期离线恢复演练。
**数据节点不安装发布写凭据、订阅 token 或管理库存。节点被接管不应获得发布权限。**

静态托管方能读取订阅内的明文节点凭据；使用自有或托管商域名都不能消除这项信任。
不使用公共转换器，不把凭据放 Git，不提供明文 HTTP 订阅；base64/随机路径都不是加密。
秘密 feed 使用 `Cache-Control: no-store`，关闭目录索引/共享缓存，访问日志去除 token/完整路径。

## 3. 一次命令完成新机与换机（提案）

以下展示**尚不存在的接口**，不是现有脚本的可复制使用说明：

```text
bash vps/setup.sh deploy --ssh root@<IPv4>
bash vps/setup.sh deploy --ssh <verified-alias> --port 2222
bash vps/setup.sh replace --ssh root@<new-ip>
```

`--ssh`是登录目标：`user@IP`、`user@DNS`或已核验的SSH配置别名，不是完整的`ssh ...`命令。
`--port 2222`仅用于需要覆盖端口时；未指定时按已核验SSH配置或默认22处理，别名也可省略此选项。
从完整仓库在管理笔记本运行；入口依赖相邻 Python/remote Bash，不能单独管道喂给远端 shell。
首次一次性选择协议/目标/版本政策、设备登记和已批准的静态发布/备份目的地；托管商域名也可用。
每台新机核验登录目标/host key、IP、实际OS/架构、专用机器、供应商与到期日；主机指纹未确认就停止，不绕过验证。
内部实例ID/显示名自动生成并持久保存，旧current自动跟踪；不要求用户命名、提供旧ID或标记旧机失联。
缺少本地状态时一次性提示首次建立还是恢复已有状态，不能猜测旧主机/身份，也不以旧机可登录为前提。
SSH引用本地agent/密钥；不硬编码两台PC公钥，不把私钥/密码贴进聊天或命令参数。

Ubuntu24.04是**操作系统版本**；`amd64`=`x86_64`是Intel和AMD都使用的64位x86架构，不是AMD品牌专属。
`arm64`=`aarch64`是另一架构；实际机器架构须先经核验SSH只读识别，不能从机型或SSH横幅猜测。
首版支持矩阵仅**专用Ubuntu24.04＋amd64/x86_64**；不匹配就停止评估，不承诺未测试的arm64支持。
一次调用顺序为：候选建立→机器事务→真实桌面/手机验收提示→明确确认→发布。
手机证据由用户实际测试后确认；无响应、拒绝或中断不得绕过验收发布。
所有替换都不要求读取、备份或登录旧节点；若旧机不可控，也不能声称已清理。

内部 `plan/add/check/promote/drain/retire/upgrade/backup/restore` 可作为排障工具，用户无需逐次手跑十步。
`plan` 离线展示脱敏变更；`check`区分服务器、桌面与手机结果；`promote`比较预期发布代次。
`backup` 输出加密恢复集；`restore`先暂存校验并显式合并，不覆盖管理机SSH身份或自动发布。

## 4. 客户端契约：导入一次，节点变更靠刷新

| 端点（示意，同源不同格式） | 消费方与用途 |
|---|---|
| `https://<hosting-domain>/s/<token>/desktop.yaml` | Verge普通导入的**完整 bootstrap profile** |
| `https://<hosting-domain>/s/<token>/nodes.yaml` | profile内部引用的Mihomo节点 provider，不是完整profile |
| `https://<hosting-domain>/s/<token>/phone.txt` | Shadowrocket独立base64 URI节点订阅 |

桌面一次性 profile 生成器提供基础规则、手动选择组和provider连接；不能把provider YAML冒充完整profile导入。[6][7]
provider显式直连下载，候选更新间隔1800秒；DNS解析、下载路径和间隔均需按实际版本验收。
节点变化只更新provider，不重导入/覆盖用户设置；规则、节点和Verge管理的TUN/端口设置各自有唯一来源。
基础profile规则升级另行预览/确认，不能借节点更新覆盖本地扩展、选择或设置。
`SELF-main`维持手选逻辑名并映射到新实例；名称保持不等于旧连接自动迁移。
若用户愿意保留已有机场，则仍为独立profile/手动回退；不要求开通，不隐式合并或强制API域名路由。

手机feed只更新节点；中国站点/Bili直连等放本地规则，不依赖未经验证的全局字段或覆盖整份规则。
Shadowrocket版本史只证明功能线存在，字段兼容、刷新、后台调度、删除缓存仍需真机验收。[8]
必要时用户手动刷新，甚至先停VPN再直连更新；不承诺iOS按固定周期后台唤醒。
“节点还显示”只证明缓存存在；“REFRESH后公钥/认证已更新且能连接”才证明恢复。
稳定URL不等于稳定IP；数据地址可每代变更，不以DNS TTL作为恢复时限。
订阅域名DNS和下载必须在旧节点完全死亡、系统仍选择旧代理时验证可用。

## 5. 两种事务，两个提交点

### 机器事务：只使候选可测试

1. 只读预检SSH信任/权限、OS架构、占用端口、已装核心、服务/防火墙归属及可用磁盘。
2. 非法目标、非专用主机、外来同名配置/服务或端口冲突时停止，不接管、不清空规则。
3. 校验可信包/配置，上传候选；原生核心检查与防火墙语法检查通过后才准备激活。
4. 保存仅本模块归属的配置、二进制/包版本及启停状态；写持久pending日志并装启动前恢复门。
5. 受保护激活，验证实际进程/版本、监听、出站约束、全新非复用公钥SSH；失败自动恢复受测组合。
6. 候选机器提交后仍未进入正式feed；生成私有临时profile/QR供桌面与手机验收。

短时独立回退timer可复用，但不能代替重启后的pending恢复；恢复途中先确保不启动未受控示例配置。
包安装/升级、配置替换、追加公钥不是同一个回滚范围；日志必须准确报告留下的变更。
保持原SSH、authorized_keys和控制台通道；加固另行确认、验证effective sshd配置后才做。
仅管理声明归属的文件/用户/unit/规则；不删除外来服务、其他表、通用软件包或网络配置。
即使只改独立nft表，input `policy drop`也可能盖掉其他链的accept；冲突拒绝比“绝不影响”承诺真实。

### 用户发布事务：验收后才使设备看到候选

1. 临时profile/QR验证唯一候选及错误认证；用户明确确认PC/手机证据，不把服务器健康冒充端到端通过。
2. 本地生成每设备完整的不可变generation，校验格式、节点映射和最新撤销集合。
3. 发布端加锁＋比较expected-generation；上传完整目录后原子切current指针，避免半文件。
4. 各客户端REFRESH并核对新代次/节点；失败保留上一有效发布供回退，不自动恢复已撤销凭据。
5. 不要求旧新实例并存；设备确认新代次后退役旧记录，旧机若仍受控才清理/排空，离线设备靠刷新恢复。
6. 移除旧feed条目、撤销旧授权、清理模块资源和云端退租分别确认；退租不自动执行。

原子性只在**单一源站**成立；镜像逐源验证代次/摘要，不声称跨源全局原子。
发布中断先查询实际current代次再重试，不能根据本地失败消息认定远端没发布。
保留回退代次时应用最新撤销集合；回滚不是让丢失设备重新获得访问权。

## 6. 版本、端口与运行约束

release-lock记录精确包版本/架构、可信签名密钥与摘要依据，以及通过验收的客户端/目标组合。
官方签名包路径或预存可信部署包缺失时明确失败；禁止自动镜像、latest或后端替换。
配置按目标版本生成/校验；重跑同一desired state不换身份、不叠规则、不无谓重启。
单节点升级先离线校验候选包/配置，安排维护停机并保留旧包及匹配配置；不假定有备用承接流量。
只回配置不能声称降级成功；不能可靠回退时重建节点。版本/租期及托管TLS状态在节点外提醒，不禁用OS安全更新。

| 组件 | 监听归属及证书 |
|---|---|
| 唯一数据节点 | REALITY占用公网TCP443；第三方目标模式无需自有域名/证书 |
| 独立静态托管 | 托管服务提供HTTPS443及可信TLS名称；不是额外租用的VPS |
| 可选self-steal | REALITY仍占公网443，本机HTTPS目标绑定loopback独立端口；先验完整握手与续证 |

ACME **HTTP-01使用公网80，TLS-ALPN-01使用公网443**；443被占用时不得假装两个进程都可监听。
可选DNS-01需另行批准DNS权限；DNS token不装数据节点。为HTTP-01设计的80服务须有明确归属。
同机8443订阅只属降级模式；公网端口与loopback目标端口不要混为一谈。
不接入Tailscale/上海中继/公司8743，不更改PC互联、Codoxear或其他既有网络。

## 7. 已经坏掉时如何恢复

| 故障 | 可执行恢复与边界 |
|---|---|
| 唯一VPS到期/全不可达 | 接受停机；租新机→replace新登录目标→候选验收→独立源站发布→REFRESH，无需旧机 |
| 等待新机期间 | 没有默认备用；仅在用户已有且愿意使用机场时手动切换，否则等待冷替换 |
| 订阅主源也不可达 | 人工切预登记独立镜像，或管理机导出新节点文件/QR；不是缓存旧节点“恢复” |
| 所有在线源都失败 | 离线恢复集重建源站或人工导入；若管理SSH也不可达，需控制台/用户另建管理通道 |
| 设备/token泄露 | 撤销源站/已登记镜像feed及当前可达服务器授权；其他设备继续工作，不必销毁正常VPS |
| 失联旧机残留凭据 | 标记清理未证实，必要时服务商停用/退租；新机换密钥或改DNS不撤销旧机 |
| 慢而非断 | 分别检查本地链路、ISP/跨境拥塞、UDP限制、服务器资源和目的站政策，再决定替换 |

订阅源迁移需维持原URL控制权；若托管商域名不可迁移或域名/SNI受阻，须人工切已登记地址或重新导入，不能只改DNS。
唯一数据节点没有在线冗余；独立订阅源只保住配置分发，不消除数据停机，也不保证它自己永远可达。

## 8. 发布验收矩阵（待实施，不执行GFW探测）

仅在自有/获授权设备、服务器和业务调用范围内模拟故障；所有结果按客户端版本、运营商与时间窗记录。

| 场景 | 必须观察到的结果 |
|---|---|
| 旧节点完全死亡，客户端仍选择它 | 桌面/手机能走独立DNS/下载路径取得新feed，或执行明确人工恢复步骤 |
| Verge首次bootstrap | 普通导入完整profile可用；provider单独不是profile；不改机场和用户TUN等设置 |
| 节点更新与快照导入 | REFRESH得到新认证且保留规则/选择；旧QR只是快照，不冒充持续更新订阅 |
| 手机与订阅源故障 | 实测手动刷新/停VPN下载、预登记镜像及离线导入，无后台/自动URL回退假设 |
| 错UUID/密码/REALITY公钥/证书 | 必须拒绝；未认证探测的fallback正常，不能关闭校验让测试通过 |
| 目的站连通与账户能力 | TLS/HTTP响应和用户授权的实际业务成功分别记录；401/403不是账户可用 |
| 坏配置/不兼容release/包不可取 | 不发布坏代次，不静默latest；旧受测组合保留或明确重建 |
| SSH中断/重启/发布中断 | SSH仍可恢复，pending可重入；源站只有完整旧/新代次，不盲目重复覆盖 |
| 幂等/冲突 | 同desired state不换身份/重启；外来服务/防火墙不受损，否则部署拒绝 |
| 撤销与回滚 | 当前服务端拒绝被撤销设备；回旧代次不复活其凭据，失联旧机残留明确报告 |
| 固定/移动网络及晚高峰 | 分开记录握手失败率、超时、p95/吞吐；小样本不推算长期封禁率 |
| 原管理机与旧节点全损 | 新管理机凭仓库＋离机恢复集重建身份/发布；缺密钥时明确失败、不静默重生 |

上线前还需确认：单VPS停机容忍、静态托管及其TLS名称/信任、客户端版本、运营商、备份目的地和新机登录目标。
这套设计承诺可替换、可撤销和可回退的机制，不承诺永不封、固定恢复时限或无人维护。
