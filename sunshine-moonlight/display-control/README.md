# Display-control host protocol

This companion owns screen selection and the managed session lifecycle without modifying Sunshine or Moonlight binaries. `host.py` accepts one bounded JSON request on stdin and writes one JSON response. An installer supplies the adjacent private `host-settings.json`; requests cannot supply filesystem paths, commands or authority claims.

The implemented host-operation adapter uses Linux KMS and the pinned Sunshine build. The root connector now uses this protocol for live selection and supervised streaming. Windows/macOS native enumeration exists; their service/graphical-session adapters and native deployment acceptance remain pending.

## Ownership

Use one controller installation and one persistent state directory per Sunshine host. Every managed launch/resume must use this controller. Concurrent GUI/direct-client/admin bypasses are outside this single-authority contract. An existing unmanaged stream is never adopted or cancelled.

`reservation.json` holds ownership across selection, preparation, launch, streaming, reconnect and release. A private capability and revision identify the owner; every successful mutation returns the next revision. The operation mutex additionally serializes whole requests, including configuration/restart work. Process exit, elapsed time, EOF, Moonlight exit0 and raw Sunshine FREE do not release ambiguous ownership.

Untouched selection can refresh or cancel after hotplug. Known owned Desktop cleanup does not require capture usability. Unknown host/process/config/application, interrupted preparation and unconfirmed issued attempts remain blocked until trusted reconciliation. No RPC force/reset exists.

## Requests

Common request:

```json
{"version":1,"action":"list","target":{"address":"100.100.20.30","port":47989}}
```

`target` is the canonical Tailnet IPv4 and Sunshine base port. The host compares it with the actual owned configuration and endpoint UUID. Requests are unique-key UTF-8 JSON, at most2048 bytes; responses are at most32768 bytes.

| Action | Additional fields | Purpose |
|---|---|---|
| `list` | — | Current native screens, mode facts, selection snapshot and ownership revision. |
| `status` | — | Ownership-only revision/phase/uncertainty; no fresh screen snapshot. |
| `enroll` | `revision` | Explicit host-operator exclusivity ceremony plus fresh qualified idle facts. |
| `acquire` | `revision`, `snapshot` | Acquire the host before interactive selection. |
| `refresh` | `revision`, `capability` | Refresh pristine SELECTING intent; returns a new revision and menu. |
| `prepare` | `revision`, `capability`, `snapshot`, `display_id` | Revalidate selection, update only output_name, restart when necessary, verify correspondence. |
| `launch`, `resume`, `observe_active` | `revision`, `capability` | Persist intent before client dispatch; then observe the matching owned Desktop. |
| `begin_release`, `finish_release` | `revision`, `capability` | Persist positive-before-cancel intent, then confirm same-generation closure. |
| `abort` | `revision`, `capability` | Cancel untouched selection or explicitly completed preparation before any launch. |
| `control_lost` | `revision`, `capability` | Retain ownership and require reconciliation. |

Capabilities are secrets: carry them only in protected stdin/transport or private state, never argv, logs or public status. Errors contain a code and sanitized detail. An ambiguous response is not proof of release; do not retry a mutating request with guessed revisions.

## Client contract

1. Present actual host `list` facts and acquire before interactive selection. `selectable` with `selection_intent:"prepare"` permits a preparation attempt; it does not claim verified capture. Current screen Hz, requested FPS and measured video FPS differ.
2. Within the acquired SELECTING lease, use official list → manual PIN/pair when explicitly unpaired → fresh list confirmation, then prepare the selected output. Pairing before a controlled preparation restart persists the instance UUID.
3. After preparation, freshly resolve the paired app catalogue using stock Moonlight's case-insensitive first-title rule. Plain list carries no IDs: require exactly one Desktop title before `launch`; the host binds its inspected `desktop_app_id` to positive `currentgame` at `observe_active`. The number is not a supported alternate CLI selector. Host also rejects Desktop title aliases and command/preparation hooks.
4. Persist `launch` before issuing official `stream`; supervise the process and confirm `observe_active`. The stock CLI is single-shot; the current connector holds the lease through that child and implements no automatic reconnect/resume loop. Any separately issued resume process must receive a fresh controller `resume` intent under the same lease before dispatch. Launch preflight refusal preserves known ownership only after fresh validation; an issued unobserved attempt remains uncertain.
5. Force `stream --no-quit-after`: this overrides `StreamingPreferences.quitAppAfter`, which controls host cancellation. The CLI QML `quitAfter` separately exits the local process and does not override that preference. After the stream ends, use `begin_release` while the owned Desktop remains positive, invoke official authenticated `quit -- HOST:PORT` **once**, then call `finish_release`. After a local quit-process timeout, obtain fresh exact releasing revision/host/receipt and idle owned-status evidence before calling `finish_release` with the still-held ticket; the host confirms same-generation closure. If status is busy/unknown/drifted or any RPC is uncertain, retain ownership. Local timeout and nonzero exit prove neither closure nor nonclosure; no second quit or guessed abort is issued.
6. On cancellation before launch, use `abort`. On genuinely uncertain control/dispatch/closure, retain the lease and report reconciliation rather than choosing a default screen or erasing state.

## Installation and evidence

The managed client acquires SELECTING ownership before official list/pair/fresh-list and requires one unambiguous Desktop title before the picker/prepare. Pairing persists Sunshine's instance UUID; preparing an unpaired host could otherwise change the UUID on restart. Busy refuses before pairing. Initial catalogue failures abort only after proving the same fresh owner. A second fresh catalogue gate remains after preparation, before launch. Ordinary controlled preparation proves UUID persistence across a restart; vendor save failure fails closed with the immediate typed `host_identity_changed`, never endpoint adoption.

The explicit local installer `commands/install-display-control.sh --reconcile-host-identity` is the only identity-transfer entrypoint. The fixed shim bytes/argv and RPC schema remain unchanged. Under permanent install+operation locks, it decodes records using the OLD settings and requires:
- E1: reconciliation_required/runtime_changed, no launch attempt, active observation or Desktop lifecycle in THIS retained lease. Previously completed/released leases are unrelated; enrollment revision arithmetic is not evidence.
- E2: enrollment, matching owner, restart_intent and previous process birth equal to the reserved generation.
- E3: no receipt issued for this restart or replacement generation; an older valid receipt is preserved.
- E4: full official package/unit/argv/binary/config qualification, verified loaded executable and process configuration environment, different generation and actual old retirement (boot change or old PID start ticks/death plus qualified new unit invocation), config digest equal to lease.after_digest and backup equal to before_digest.
- E5: a valid new public UUID, FREE/currentgame0; idle alone proves no closure.
- E6: freshly discovered settings differ ONLY in host_uniqueid; apps/assets and Desktop agree.
- E7: raw local TTY REBIND confirms exclusivity, no unmanaged/in-flight stream, no concurrent edits, and completed official PIN pairing.
- E8: repeat all stable runtime/endpoint/settings/record/lock/reference facts after confirmation.

Every evidence miss precedes mutation. A verified durable `identity-transition-<id>.bak` binds UUIDs, generations, manifest, old record digests/inodes, lock identities and attestation. Rename-only archives retain operation/reservation/backup/old receipt bytes, inodes, permissions and mtime; permanent lock inodes stay in place. A fresh operation baseline has no enrollment/reservation/receipt and the new settings version is UNENROLLED. Version hashing includes host-settings.json. The same explicit command resumes a journal-bound interrupted sequence only with exact evidence/UUID/source/settings; exact partial version publications may be completed, while unknown or incomplete bytes refuse without deletion. Ordinary install remains strict host_mismatch/settings_conflict. No vendor configuration mutation, service operation, extra onboarding restart or receipt gate is introduced. After success, enroll locally, then use ordinary controlled preparation to establish UUID persistence. See the [operator recovery sequence](../README.md#在已安装的-a-独立安装显示控制伴随程序).

### Failed preparation with positively no launch: local ENROLL

The existing fixed-shim `quick-deploy-display-control --enroll` also retires exactly two same-UUID failed preparations. Use the host user's interactive terminal and the existing `ENROLL` exclusivity/no-unmanaged-or-in-flight-stream/no-concurrent-admin-edits confirmation. There is no new flag, RPC, reset command, quit, restart, config rewrite, capability adoption or receipt issuance.

Both cases require `reconciliation_required/runtime_changed`, no attempt/active/Desktop, the exact known preparation lease, matching owner/enrollment/reserved previous process birth and original topology. The old birth must be positively retired: normalized different boot, or an exact absent/dead/reused birth together with a qualified newer invocation. A different PID, caller exit, elapsed time or FREE alone cannot retire it.

- **`restart_intent`**: backup B matches `before_digest` and the reserved config; in-memory `select_output(B, selector)` produces exact A/`after_digest`; disk equals A. This includes the observed Y before=after case.
- **`rolled_back_requires_reconciliation`**: the coordinator's recorded successful CAS rollback requires B≠A and disk exactly B. This covers the company retained preparation: a process may still run A while disk is B. Recovery neither writes A nor labels it the actual disk/loaded fingerprint. `loaded_digest` and capture may remain unverified; the original prepare refusal is not repaired by publishing idle.

The fixed NSS installation, current active prefix and immutable source/settings manifest, permanent locks, trusted previously independent build qualification and exact executable SHA, full unit/process/config-root/environment/endpoint/Desktop facts must agree before/after confirmation and before commit. During a pending preparation, only a fully current receipt from **that exact restart intent**, matching its issuer, previous generation and preserved enrollment, can bridge restricted current `/proc/exe` or process config-root access. Otherwise both current accesses must be verified. A receipt is optional for idle authority, but every present receipt must bind its own typed issuance, successor birth, host/build/unit/root/environment/Desktop and known full A/B config context. Same-boot prior ordering needs actual birth ordering; another boot proves only retired/noncurrent preservation, not chronology relative to the reservation. An unrelated current/post-reboot issuer contradicts a pending intent and refuses even with readable proc. Independently issued later current receipts remain valid on **committed read-only replay**; preservation never grants new startup authority. Unexplained receipt context—including changed unit/environment/root—refuses. The two-field receipt `qualified_build` is compared to the installed typed build, not to the settings object containing additional qualification provenance. These rules do not establish admission for a particular host from partial diagnostic comparisons.

Recovery deliberately needs no native DRM/capture enumeration and does not download/requalify a reference package. Its source of qualification is the verified immutable installed provenance chain, not a self-hash of arbitrary current files. The final binding uses **fresh current generation and actual disk digest**, retaining only the original **historical** topology digest. Available grants no screen authorization: ordinary list/acquire refresh native metadata/topology, and prepare/launch must establish fresh selected-output proof.

A durable `unlaunched-transition-<id>.bak` binds original records/history/active prefix/lock identities before mutation. Publication uses the owned-release ordering: reservation rename first while the old lease blocks old ENROLL; invalid sentinel before operation-lease removal; then readable unacquirable SELECTING; original receipt/backup inodes archived with mode/mtime and identical live bytes restored. Enrollment remains unchanged. The intended journal's exact bytes and identity are pinned, not freshly hashed from whatever happens to be on disk. The descriptor binds that journal and the complete **actual** blocked live baseline: exact operation/enrollment, optional receipt or its proper absence, backup, and owned SELECTING reservation, with their identities. Intermediate missing-copy allowances permit legitimate cuts before readiness, never final readiness; after a descriptor exists, missing/changed live copies refuse rather than being silently restored. The descriptor must remain present with its intended bytes and per-invocation pinned identity through the last repeated checks. Its own byte-identical inode replacement across invocations is not claimed detectable: replay validates exact typed contents and semantics. Original archive/history/lock identities stay durably sealed, and the journal identity is bound by the descriptor. After the final external runtime/endpoint observations, every physical original archive (or its bound absence) is re-read against original bytes and recorded identity, together with the remaining filesystem readiness checks. Restored live copies cannot substitute for originals, and no further external observation intervenes before publication. The existing operator race boundary after the final filesystem check remains. The sole final atomic reservation replacement then exposes ownerless, lease-free available at R+1, without attempt/Desktop/active/uncertainty. R+1 is derived from the decoded **original archived reservation**, not a journal-declared or self-resealed floor; its enrollment/config/blocked-state promise is also checked against original records. Any later BUSY/drift leaves ownership blocked, including after descriptor creation. Exact pending replay resumes without a second confirmation; committed replay classifies the actual original-derived floor before requiring precommit source/live bytes, preserves legitimate later leases/source appends/receipts, and refuses below-floor rollback. Ordinary lifecycle/RPC enrollment still cannot clear a managed lease.

If any proof is missing, retain the reservation and all records for bounded host-local qualification; do not delete state or retry with a generic reset. Driver alignment, an authorized reboot, or a separately qualified root-access correction are separate from retirement of idle authority. After retirement, use the ordinary connector and explicit picker; capture failure still refuses launch.

A distinct explicit **local** `commands/install-display-control.sh --reconcile-owned-release` handles only a recorded `reconciliation_required/owner_lost` after a positive observed Desktop, persisted `releasing` intent and one already-issued official quit. It requires matching owner/attempt/prepared/release revisions and cancel transaction, unchanged qualified UUID/generation/config/Desktop/current receipt, a fresh FREE/currentgame0 endpoint, and raw TTY `RELEASE` attesting exclusivity, no unmanaged/in-flight stream or concurrent administrator, and the recorded official quit. The install+operation locks span qualification, repeated facts and durable writes. Original reservation/operation/receipt/backup records move verbatim into bound `.bak` archives; permanent lock inodes and earlier history/active prefix are sealed. A durable journal precedes every rename and binds the exact source/manifest while the release state is precommit. After availability commits, a later qualified source append may occupy the next active reference even if the repair's source publication was skipped. The old reservation is archived first: its missing-state interval remains blocked by the old operation lease, then an invalid private reservation blocks both old and new dispatchers while operation/receipt/backup replacements are prepared. A readable but unacquirable reservation follows the new operation record. After the last qualified closure observation, a durable descriptor is sealed **before** the final atomic reservation publication; that publication alone exposes available at the **next** revision. An interrupted precommit attempt stays blocked, even if a later endpoint observation contradicts earlier FREE; a committed replay checks the sealed revision floor and permits legitimate later leases. Original backup remains archived and an identical live backup supports future no-op preparations. Enrollment and the valid receipt remain, and no re-enrollment is requested. Bad evidence refuses before the availability commit; initial bad evidence/lock contents cause no record mutation. This command never quits/restarts Sunshine, edits vendor config, changes UUID, publishes a system shim or extends the identity-transfer path; public FREE by itself is insufficient. See the [operator recovery sequence](../README.md#在已安装的-a-独立安装显示控制伴随程序).

### Attempted launch with no positive active observation: local RETIRE

After normally publishing this exact candidate with `commands/install-display-control.sh`, run **locally as the Sunshine desktop user**:

```sh
bash commands/install-display-control.sh --reconcile-attempted-launch
```

The command opens `/dev/tty` and asks for `RETIRE`. Its warning authorizes **one Sunshine user-service STOP and one START**. Before confirming, stop all old Moonlight clients, coordinators and helpers, exclude every other client/authenticated replay sender, and hold the sole-entry/no-concurrent-administrator window through completion. This operator contract is necessary; it does not replace current machine qualification. The command selects the installation and user manager through NSS and fixed `/run/user/UID` paths, ignoring caller HOME/XDG/D-Bus selection. No downloads, sudo, shim change, RPC action, quit, re-pairing, configuration rewrite, vendor update or physical display change occurs in this ceremony.

This is a **distinct retirement authority**, not an ENROLL, RELEASE or REBIND fallback. Only an exact enrolled `owner_lost`, attempted-but-never-positively-active reservation with matching `attested` preparation/owner/positive known empty-command, no-prep/no-detached/no-global-hook Desktop is admitted. The original binding/current controlled-start receipt, backup-to-selected config, current disk, supported build, unit, process/root/environment, UUID/base endpoint and FREE/currentgame0 must agree. Arbitrary busy/active/releasing/foreign identities and restricted or unknown facts refuse before service control. FREE, caller death, log absence and a changed MainPID alone never grant recovery authority.

The installer holds the permanent installation and operation locks across one monotonic transaction:

1. Seal the original reservation/operation/receipt/backup physical identities, history, references and locks in an immutable intent while ownership remains blocked.
2. Persist `stop-issued`, dispatch the exact canonical user unit's blocking STOP, and persist `stop-completed` only after the acknowledged command child has exited and been reaped. A stop acknowledgement alone proves no Sunshine extinction.
3. Collect a typed **StopWitness**: same old boot/unit/UID/invocation/PID birth, terminal `inactive/dead`, MainPID0/ControlPID0, no jobs or restart transition, positive exact-birth retirement and **hierarchical** old cgroup-v2 `populated=0` (including descendants), or positively qualified removal of that stopped scope. KillMode=control-group, SIGKILL/final9/stop90s, on-failure restart, no delegation/activation/FD store/stop hooks and the pinned unit/build path are mandatory. Native `Job=` must be explicitly present and empty. The separate `busctl --json=short ... call ... ListJobs` response must be exactly typed `a(usssoo)` with one empty array return value: `"data":[[]]`. Method-call JSON wraps return arguments; flat `"data":[]`, omitted/extra arguments, malformed rows or unknown signatures refuse. A valid nonempty job array refuses under the unchanged global-quiescence guard, including jobs for other units. A separate empty-array method capture establishes codec shape only, never ListJobs quiescence or retirement. Missing, numeric-zero or nonempty unit Job also refuses. The current active/populated scope and historical inactive timestamps are never stopped evidence. Inaccessibility is unknown, not death; empty top-level `cgroup.procs` is insufficient.
4. Persist the StopWitness **before** `start-issued` and START. The witness cannot be reconstructed from a reused/populated successor cgroup. Persist acknowledged/reaped `start-completed`, then require a fresh stable same-UUID/unit/UID/root/build/config/Desktop and idle successor. No old sender may remain to replay authenticated work or issue late service controls.
5. Rename/archive all four originals without changing bytes, device/inode, mode or mtime. Preserve enrollment, prior histories/reference prefixes and permanent lock inodes. Use the existing missing-reservation/old-lease → invalid sentinel → lease-free unacquirable SELECTING ordering, so even old dispatchers cannot bypass an incomplete compound repair. A durable descriptor binds intent, phase proofs and the complete live blocked baseline. After the last external observation, recheck **all** original archives, restored live records, intent/descriptor/phase identities, histories, references, installation and locks. Only then atomically replace the reservation with ownerless AVAILABLE at **original R+1** (R60 only if original R59 is unchanged).

Before publishing any intent or issuing STOP, RETIRE serializes a complete upper-size specimen for the intent, all seven phase records and final reservation. The existing private JSON limit remains **32768 bytes** (reservation:16384). The specimens preserve every original hex byte and unchanged admitted context, and bound only future choices: ownership PID uint32, ticks/monotonic below2^63, longest accepted terminal/witness strings, and checked Linux stat64 dev/inode/time_t domains for new0600 own-user record identities. Size specimens are discarded, never used as runtime or receipt evidence. Every actual phase is also checked against its preflight ceiling before create. A larger valid config/receipt or extensive metadata can therefore be ineligible for RETIRE: the refusal names the overflowing serialized record and leaves originals unchanged, creates no intent/phase and issues zero controls. Eligibility depends on the complete serialized context, not a fixed small config-size cutoff; ordinary configuration support through1MiB is unchanged. Do not truncate records or retry service controls to bypass this refusal.

The command prints a JSON success with the new revision/phase or a sanitized refusal on stderr and exits1. An interruption can leave `.bak` phase evidence and blocked ownership. Rerunning this same explicit local command never repeats an issued STOP/START. It can resume after a durable completed/reaped STOP and a directly observed stopped old scope, or after a durable completed/reaped START and a genuinely qualified successor tied to that persisted witness. A marker without durable control-completion proof refuses **even if the unit is now inactive, has no jobs, or has a new PID**: an orphaned control sender might still issue a late STOP. Stop/start failures, uncertain issuance and crashes before the completion record require a separately approved, bounded operator intervention; automatic completion is not promised. Do not delete records, manually reset FREE, adopt the capability, or substitute ENROLL/RELEASE. Committed read-only replay preserves legitimate later leases, receipts and source publications while enforcing the original-derived monotonic floor and original evidence.

The old receipt stays verbatim in its archive and as historical live evidence. RETIRE issues **no new StartReceipt**, loaded digest or capture proof. The new available binding uses the fresh generation and actual disk digest, retaining only validated historical topology; ordinary next prepare must prove the selected capture and issue any required controlled-start receipt. Descriptor identity is pinned within an invocation; cross-invocation descriptor replay promises exact content/semantics, not an unimplemented durable self-inode guarantee. Source tests (`bash tests/run-attempt-retirement.sh -v`) use private installed-source/kernel-like fixtures and mock service controls, not native retirement acceptance.

Settings schema2 pins the user service/config/apps/assets/state paths, host UUID/base port, qualified executable/source provenance and retry-guard digest. `commands/install-display-control.sh` verifies the exact reference package against installed bytes; hashing arbitrary installed files is not qualification. See [installation instructions](../README.md#在已安装的-a-独立安装显示控制伴随程序). Private settings/receipts are0600 and state is0700. Installation does not enroll or restart; fixed system shim publication requires explicit `--publish-shim`, and enrollment is a local interactive `quick-deploy-display-control --enroll` ceremony, unavailable through ordinary stdin RPC. Installed execution uses `-I -B`; complete RPC responses, including refusals, exit0 and must be interpreted from JSON. Local enrollment failures exit1.

A controlled-start receipt is issued only after an owned restart, old-generation retirement, new matching endpoint, stable qualified files and completed source-matched probe.

Native inventory, effective backend/encoder, selected connector correspondence and captured-image/live-frame evidence are distinct. Fixture suites exercise the real JSON/coordinator/state/config path using injected runtime/native/endpoint facts. They do not establish Windows/macOS runtime support or live selected-image acceptance. Real switching must use an explicitly available host; never interrupt an existing stream for testing.
