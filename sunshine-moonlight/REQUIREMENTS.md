# Sunshine / Moonlight：Linux 双向远程桌面需求

本文记录已确认的使用目标、修改边界和验收标准，不代表这些能力已经全部实现。

## 1. 总体目标与范围

公司电脑和 Y 电脑均可作为 Sunshine 主机或 Moonlight 客户端，实现 **Linux ↔ Linux 双向远程桌面使用**。

- 本轮只考虑 Linux，不投入 Windows、macOS 等非 Linux 系统的连通适配。
- 日常使用通过统一入口 `run_server.sh <机器名>` 发起，不要求每次手工 SSH 到远端、修改配置或重启服务。
- 必要的安装、配对和权限配置可以作为初始化步骤；完成部署后，正常使用不应依赖到远端现场操作。

目标使用方式示例：

```bash
# 公司电脑作为客户端，连接 Y
./sunshine-moonlight/run_server.sh conley-Y9000p

# Y 电脑作为客户端，连接公司电脑
./sunshine-moonlight/run_server.sh conley-company
```

## 2. 必需的使用场景

### 2.1 刚开机、尚未登录桌面

- Linux 已启动到系统登录界面、用户尚未登录桌面时，也能通过 Moonlight 连接。
- 用户在 Moonlight 中输入登录凭据，进入可用桌面，无需先到主机本地登录。
- 登录界面到用户桌面的切换必须有可用的连接衔接方式，不能因此要求现场处理。
- 不把“只能连接已经登录的用户会话”视为本需求完成。

### 2.2 已登录后的锁屏与熄屏

- 远端已登录但处于锁屏、显示器省电熄屏状态时，仍可从客户端发起连接。
- 允许连接过程中按需唤亮远端显示输出，**可以同时点亮多块物理屏幕**。
- 唤屏与解锁分开：保持系统登录认证，由用户自己在 Moonlight 中输入密码。
- 不以永久关闭锁屏或省电作为解决方案；后台状态检查不得持续唤屏。

## 3. 屏幕枚举与选择

### 3.1 实时信息

连接时展示远端当前的屏幕信息，包括：

- 屏幕名称及可区分的身份信息；
- 连接、亮灭、可用或不可用状态；
- 当前分辨率与物理刷新率；
- 不可选择时的明确原因。

信息必须来自当前实际状态。熄屏等情况下无法确定的模式应标为未知或待唤醒，必要时唤醒后重新读取；不能用支持的最大模式冒充当前模式。

### 3.2 明确选择、准确捕获

- 支持 Up/Down 方向键选择，Left/Right 可作为同义操作；Enter 确认，Esc 取消。
- 用户明确选择哪块屏幕，就必须捕获该屏幕。
- 不能仅凭相同分辨率认定是同一块屏幕。
- 所选屏幕不可用时，应说明情况并让用户重新选择，不能未经确认改播另一块屏幕。
- 菜单可以预选一个目标，但预选不等于连接失败后可以擅自换屏。

公司 → Y 的 DP-1、Y → 公司的 DP-2 是当前两条基础验收线路，不是写死的唯一支持对象。名称或编号变化时，应重新核验实际屏幕身份。

## 4. 低延迟与画质取舍

**低延迟、操作跟手优先于原生分辨率和最高画质。**

- 允许降低串流视频分辨率、牺牲画质，以降低延迟。
- 不要求固定 4K，也不要求必须按远端物理屏幕的原生分辨率输出视频。
- 降低串流分辨率不必同时改变远端物理显示模式；两者应明确区分。
- 具体分辨率、码率、帧率和编码策略由实施方案与实际表现决定，不预先把某组参数当作完成标准。
- 画面应足以辨认登录界面和日常操作内容。

主要验收依据是拖动窗口、点击菜单、文字输入等操作的实际响应，不能只看本地光标是否移动。物理刷新率、请求的视频 FPS、实际接收/渲染 FPS 和交互延迟是不同指标，不能相互替代。

## 5. 会话、退出与恢复

- 受管连接通过统一入口发起，不抢占其他正在使用的会话。
- 正常退出后应确认释放会话及预约，之后可以再次连接。
- 正常的连接、退出和重复使用，不应依赖手工删除状态或反复修复预约记录。
- 遇到真正不确定的会话或控制状态，应明确报错、保留证据，并提供可执行的恢复路径。
- 不得把客户端退出、超时或单个空闲状态值直接当作会话已正确关闭的证明，也不得用重置状态掩盖失败。

## 6. 修改边界与用户数据

### 6.1 保持不变

- **不修改 Sunshine 官方源码，不替换或修改其官方二进制。**
- 保留已有凭据、配对关系、SSH 信任与配置、用户工作及必要的历史证据。
- 密码由用户本人输入；代理不读取、记录、保存或代输登录密码。
- 不因本任务顺带升级驱动、重配网络代理、改变桌面布局或永久关闭省电与锁屏。

### 6.2 可纳入具体实施方案的内容

以下属于实现手段与修改范围，不是额外功能需求：

- 本项目连接器、伴随控制程序的必要改进；
- Sunshine 官方程序已有的本机配置选项；
- 与 Sunshine 启动时机、运行账户、会话依赖有关的 Linux 服务配置。

本机配置和启动设置不是无限制修改授权。实施前应列明**具体改项、必要性、影响和回滚办法**，与用户确认；不能未经验证就认定必须固定某个编码器、增加常驻服务或调整系统权限。

## 7. 可选增强：整机远程唤醒

如果硬件、固件和网络条件允许，尽量支持整机休眠或关机后的远程唤醒，例如 Wake-on-LAN。

这属于可选增强，不应阻塞“主机已经开机、停在系统登录界面时可以连接”的必需能力。应明确实际支持条件，不作未经验证的可用性承诺。

## 8. 验收标准

两台 Linux 电脑分别作为客户端和主机，均需完成以下验证：

1. 从系统登录界面连接，并通过 Moonlight 登录到可用桌面，无需主机现场操作。
2. 从已登录、锁屏且熄屏的状态连接，允许按需唤亮多屏，并通过 Moonlight 解锁。
3. 实时屏幕列表与实际状态一致，明确选择的屏幕与最终画面一致，不误播其他同分辨率屏幕。
4. 允许采用较低视频分辨率或画质，实际拖窗、点击和输入响应跟手，连续使用时画面正常更新。
5. 正常退出后能够再次连接，预约及会话正确释放，不影响其他用户工作。
6. 整个实现符合官方源码和二进制不改、凭据保留、具体配置改动事先确认的边界。

整机休眠/关机后的远程唤醒单独记录验证结果，不与上述必需项混为一谈。
